# ひがやいびん

「やること」と、それに紐づく情報（メール・添付・メモ）を、ひとつのページでまとめて見られるタスク管理。
もとは2号店オープンの準備のために作りましたが、誰でも、ふだんの用事に使えます。

## 今できること（第1段階：ページと保存）

- **プロジェクト**：やることを入れる大きな箱（例：「仕事関係」「ウエディング」「日常生活」）。
  最初の画面で、作る・押して開く・名前を変える・なくす（なくしても項目は消えず、「プロジェクトなし」になる）。
  一度閉じても、最後に使ったプロジェクトが開く。左上のプロジェクトの名前を押すと、最初の画面に戻る。
  項目は、編集の中の「プロジェクト」でほかへ移せる。プロジェクトを使う前からあった項目は「プロジェクトなし」に入っていて、
  最初の画面からまとめてプロジェクトに入れられる。メールの候補と通知は、プロジェクトをまたいで共通
- やることの追加・編集・完了・削除（内容 / カテゴリ / 必要な対応 / 進捗〔まだ・途中・返事待ち〕/ 誰に任せるか / 期限）
- **カテゴリ**：項目に大まかなカテゴリをつけて、一覧の上のボタンで絞り込める。
  カテゴリは追加や編集のときに「＋ 新しいカテゴリを作る」で増やせる（「① …」「② …」のように番号をつけると、その順に並ぶ）。
  絞り込み中に追加すると、そのカテゴリが最初から選ばれている。
  カテゴリのボタンを押して選ぶと、その下に「カテゴリの名前を変える」「このカテゴリをなくす」が出る（なくしても項目は消えず、カテゴリなしになる）
- **項目を押すと編集**：項目のどこを押しても編集が開く（完了の丸とリンクは除く）
- **削除は左にスワイプ**：項目を左にスワイプすると「削除」が出る。編集の中にも「削除」がある（パソコンではこちら）。
  間違えて消しても、直後に出る「元に戻す」で戻せる
- **ひとことで追加・声で入れる**：「内容」に「金曜までに見積もりを頼む」「明日 歯医者に電話」と入れると、期限の欄に日付が入る
  （期限を自分で入れたときは、そちらを優先）。
  「内容 …、対応は …、進捗は途中、担当は自分、期限は金曜」のようにキーワードをつけると、欄ごとに分かれる
  （キーワード：内容・カテゴリ・対応・進捗・担当・期限・繰り返し。追加の前に、どう分けたかが出る。
  カテゴリは、いまあるものに合うときだけ入る。合わなければカテゴリなしで追加される）。スマホのキーボードのマイクで話せば、打たずに入れられる
- 「AIにまとめてもらって追加」：やることを話し言葉のままAIに伝え、返事を貼り付けてまとめて追加（確認してから追加。お願い文は画面からコピーできる）
- 期限の近い順に表示
- **直近**：期限が3日以内のもの（今日・期限切れを含む）は、カテゴリに関係なく、一番上の「直近」にまとまる。
  カテゴリのボタンの数字は、その下の一覧に出る件数（直近のものは数えない）
- **期限の色**：期限まで2日を切ったら赤（期限切れ・今日・明日）、5日以内は黄色、それより先は緑
- **メモと履歴**：項目を押すと、編集の下に出る。メモを書いて「保存する」を押すと、日時つきで残る。
  メール・添付も同じ並びに、古い順で出る。添付は種類（PDF・写真）がわかり、1回押すと開く
- **探す**：内容・相手・メモ・メールの件名と差出人から探せる（全角・半角、カタカナ・ひらがなの違いは気にしない。
  空白で区切ると、全部の言葉が入っているものだけ）。検索中は、完了した項目とメールの候補も出る。
  「よく出る言葉」は、やること・メモ・メールによく出てくる言葉で、押すとその言葉で探す
- **繰り返し**（お試し）：毎日・毎週・毎月・毎年を選べる。完了にすると、次の回の項目ができる
- **はじめての人への案内**：項目が1つもないときに出る。「例を3件入れてみる」で試せる
- 完了した項目は下にまとめて薄く表示
- スマホとパソコンの両方の画面幅に対応
- Supabase に保存してログインで守る（設定したとき）

## 通知（第2段階：朝と夕方の報告）

毎日、朝と夕方（夜）の決めた時刻に、その時間帯に起きたことを、スマホの通知でお知らせします。
Supabase に保存しているときだけ使えます。

- **時刻は人ごとに選べます**（最初は朝10時・夕方17時。日本時間）。ページの「通知」欄で、朝は4〜12時、夕方・夜は13〜23時から選びます。
  片方を「受け取らない」にもできます。変えると、次の回から新しい時刻に届きます
- 伝えるのは、前の回の報告からその回までに起きたこと（最初の時刻なら、朝：前日17時〜当日10時 ／ 夕方：当日10時〜17時）
- 中身は、やることの追加・期限の変更・完了・削除と、期限の近い件数（「本日まで：0件　翌日まで：0件　3日以内：0件」の形。期限切れも含めて数える）
- 通知を押すとページが開き、その回の報告が一番上に出て、関係する項目に枠がつきます
- メールの連携を設定すると、その時間帯に届いたメールの要点（誰から・件名・添付の数）も加わります。
  **緊急のメールは、報告を待たずにその場で通知します**（下の「メールとドライブの連携」）

### 最初の設定（1回だけ）

1. **通知を送るプログラムを Supabase に置く**
   Supabase の画面で「Edge Functions」→「Deploy a new function」→「Via Editor」を開き、
   名前を `report` にして、`supabase/functions/report/index.ts` の中身をそのまま貼り付けて Deploy します。
2. **「Verify JWT」をオフにする**
   作った `report` の設定（Details）で「Verify JWT with legacy secret」をオフにして保存します。
   （時刻の予約からの呼び出しを通すためです。本人確認はプログラムの中で行っています）
3. **テーブルと時刻の予約を作る**
   「SQL Editor」に `supabase/add-notifications.sql` を貼り付けて、Run を1回押します。
4. **iPhone のホーム画面に追加する**
   Safari でページを開き、共有ボタン →「ホーム画面に追加」。以後はホーム画面のアイコンから開きます
   （初回はもう一度ログインが必要です）。
5. **通知を受け取る**
   ページ下の「通知」欄で「通知を受け取る」を押し、許可します。
   「今すぐ試しに送る」を押して、通知が届けば完了です。

### 仕組み

- やることの追加・期限の変更・完了・削除は、データベースが自動で記録します（`item_events`）。
- Supabase（pg_cron）が毎時0分に `report` を呼び、`report` が、その時刻を選んでいる人の分だけ、時間帯の記録をまとめて通知を送ります。
- 同じ時刻の報告は1度しか送りません。
- 通知の署名に使う鍵は `report` が初回に自動で作り、ページからは読めないテーブルに保存します。
- ログアウトすると、その端末への通知は止まります。
- 「通知」欄は、選び終わると畳まれます。ページの一番下の「通知の設定」を押すと、また開けます（試しに送る・やめる）。

## ログイン・新規登録・アカウントの切り替え

Supabase に保存しているとき、最初の画面で「ログイン」と「新規登録」を選べます。

- **新規登録**：メールアドレスと、自分で決めたパスワード（8文字以上）を入れて「登録する」。
  Supabase の設定で「メールの確認」がオンのときは、確認のメールが届くので、その中のリンクを押すと登録が完了します。
- **アカウントの切り替え**：一度ログインしたアカウントは、その端末が覚えます。
  右上の「アカウント」を押して、切り替えたいアドレスを押すだけで切り替わります（パスワードの入れ直しは不要）。
  ログイン画面にも「この端末で使ったアカウント」として出ます。
- 端末が覚えるのは、ログインした状態を保つための鍵だけで、パスワードは保存しません。
  ログインしたままにしているのと同じ扱いなので、**ほかの人と共有する端末では、使い終わったら「ログアウト」** してください
  （ログアウトしたアカウントは、その端末の一覧から消えます）。
- やること・通知・メールの連携は、アカウントごとに別々です。ほかのアカウントの内容は見えません。
- 通知は、その端末でいま使っているアカウントの報告が届きます。

### Supabase の側で確認しておくこと

- 「Authentication」→「Sign In / Providers」で **Allow new users to sign up** がオンになっていること（オフだと新規登録できません）。
- 確認のメールのリンクからページに戻れるように、「Authentication」→「URL Configuration」の **Site URL** に、公開しているページのアドレスを入れておきます。
- ページのアドレスを知っている人は、誰でも新規登録できます（登録しても、ほかの人の内容は見えません）。
  誰でも使える形にするので、オンのままにします。「Confirm email」（メールの確認）は必ずオンにしておきます。

## メールとドライブの連携（第3段階）

Gmail で決めたラベル（最初は「ひがやいびん」）をつけたメールが、ページの「メールからの候補」に出ます。
添付は Google ドライブに保存され、やることの項目にリンクがつきます。

- 候補は、確認してから「やることに追加」を押したものだけが、やることになります（勝手には追加されません）。
  新しい項目にするか、いまある項目にリンクだけつけるかを選べます。いらない候補は「追加しない」。
- **入れ先の提案**：候補ごとに、どこに入れるとよさそうか（プロジェクト・カテゴリ、または「この項目に足す」）が出ます。
  「やることに追加」を開くと、提案が最初から選ばれています。変えるのは自由です。提案の決め方は、
  同じ件名のやりとりがついている項目 → 同じ差出人のメールを前に入れたところ → 似た言葉のやること、の順（AI は使いません）
- **緊急のメール**：次のどれかに当たるメールは、届いた回（30分おきの確認）にその場で通知し、ページでは一番上の「直近」に、
  期限の近いやることと並べて出します（どのプロジェクトを開いていても出ます）。
  - 「大事な相手」に入れた人から届いた
  - 件名か本文に「至急」「本日中」「督促」などの言葉がある
  - 3日以内の期限が書かれている（「11月18日までに」「お支払い期限：11/19」など）
- **ラベルの名前と「大事な相手」は、ページの「メールの連携の設定」で決められます**（合言葉を作ったあと）。
  ラベルの名前を変えると、次の確認から新しいラベルを見ます（Gmail にそのラベルがなければ、自動で作られます）
- 見るのは、そのラベルのついたメールだけです。メールの送信・削除・既読への変更はしません。
  （Gmail の「フィルタ」で、決まった相手から来たメールに自動でラベルをつけると便利です）
- 自分が送った返信は候補にしません。確認は30分おきです。
- **添付の保存先**：ドライブのフォルダ「ひがやいびん 添付」の中に、月ごとのフォルダ（例：`2026-11`）ができ、
  ファイルは「日付_差出人_もとの名前」（例：`2026-11-14_山田工務店_請求書.pdf`）で入ります。
  ページの項目では、種類（PDF・写真）と名前が出て、1回押すと開きます
- 添付のフォルダは、Gmail の持ち主だけが見られる状態で作られます。共有するときは、必要な人だけにしてください。
- 届いた候補（差出人・件名・本文の最初の部分）は Supabase に保存され、ログインした本人だけが読めます。

### 最初の設定（1回だけ）

1. **受け取り口を作る**
   Supabase の「SQL Editor」に `supabase/add-mail.sql` を貼り付けて、Run を1回押します。
2. **通知のプログラムを新しくする**（緊急のメールの通知と、報告にメールの要点を入れるため）
   「Edge Functions」→ `report` を開き、`supabase/functions/report/index.ts` の中身を貼り付け直して Deploy します。
   続けて、「SQL Editor」で `supabase/add-notifications.sql` をもう一度 Run します。
3. **合言葉を作る**
   ページの一番下の「メールの連携の設定」→「合言葉を作る」を押し、出てきた合言葉をコピーします。
   （合言葉が見えるのはこのときだけです。人には見せないでください）
   ラベルの名前を変えたいときは、ここで「見るラベルの名前」を書いて「この設定を保存する」を押します。
4. **Gmail の側のプログラムを置く**
   メールを受け取りたい Google アカウントで https://script.google.com を開き、「新しいプロジェクト」を作ります。
   最初から入っている文を全部消して、`google/mail.gs` の中身を貼り付け、保存します。
5. **合言葉を入れる**
   左の歯車「プロジェクトの設定」→ 一番下の「スクリプト プロパティ」→「プロパティを追加」で、
   名前（プロパティ）に `TOKEN`、値に 3 でコピーした合言葉を入れて保存します。
6. **setup を1回実行する**
   エディタに戻り、上の関数の選択を `setup` にして「実行」を押します。
   Google の許可の画面が出るので、自分のアカウントを選んで許可します
   （「このアプリは確認されていません」と出たら、「詳細」→「（プロジェクト名）に移動」。自分で置いたプログラムなので問題ありません）。
7. **試す**
   Gmail でメールを1通選んで、決めたラベルをつけます。30分以内（すぐ試すなら、関数 `run` を実行）に、ページに候補が出れば完了です。
   ページの「メールの連携の設定」に「連携しています（最後の確認：…）」と出ます。

### うまくいかないとき・やめるとき

- 候補が出ない：ページの「メールの連携の設定」で、最後の確認の時刻を見ます。
  時刻が出ていなければ、Apps Script の左の「実行数」で失敗の理由を見ます（合言葉の入れ間違いが多いです）。
- 緊急の通知が来ない：ページの「通知」欄で「通知を受け取る」になっているか、`report` を貼り付け直したかを確かめます。
  候補に「緊急」の印がついていれば、判定はできています。
- 合言葉を作り直したら、Apps Script の `TOKEN` も入れ替えます。
- やめるとき：Apps Script で関数 `stop` を実行し、ページの「メールの連携の設定」→「連携をやめる」を押します。
  届いた候補と、ドライブに保存した添付は残ります。

### 仕組み

- Gmail の側のプログラム（Google Apps Script）が、30分おきにラベルのメールを見て、まだ届けていないメールだけを届けます。
  添付はそのときドライブに保存します。同じメールを2度届けることはありません。
- 届け先は Supabase の受け取り口（`receive_mail`）で、合言葉が合ったときだけ受け取ります。
  Supabase には合言葉そのものは保存せず、照合用の値だけを持ちます。
- 届け終わると、Gmail の側のプログラムが `report` に知らせます。`report` が、まだ判定していない候補を決まりで判定し、
  緊急のものだけを通知します。届いてから2時間以上たった候補は、判定だけして通知はしません。
- メールから「やること」の文を自動で作る（AIの要約）ことはしていません。件名を「内容」の下書きにして、追加の前に直せます。

## 保存について（大事）

`config.js` が空のあいだは、**開いた端末のブラウザの中** に保存します（同期なし・ログインなし）。

`config.js` に Supabase の Project URL と Publishable（anon）キーを入れると、
Supabase に保存するようになり、ログイン画面が出ます。ログインした本人の項目だけが読み書きできます。
テーブルの定義は `supabase/schema.sql` にあります。

すでにテーブルを作ってある場合、カテゴリを使うには、SQL Editor で `supabase/add-category.sql` を1回 Run してください
（実行するまでは、カテゴリをつけた項目だけ保存できません。カテゴリなしの項目は今までどおり使えます）。

## 開き方

ビルドは不要です。`index.html` をブラウザで開くか、次のように配信します。

```
python3 -m http.server 8000   # → http://localhost:8000
```

## テスト

```
node --test
```

| `supabase-store.js` | 保存とログイン（Supabase） |
| `config.js` | Supabase の接続先 |
| `supabase/schema.sql` | Supabase に作るテーブル |
| `supabase/add-category.sql` | 「カテゴリ」の欄を追加する（すでにテーブルがある場合） |
| `supabase/add-notes.sql` | 「メモ」と「繰り返し」の欄を追加する（すでにテーブルがある場合） |
| `supabase/add-projects.sql` | プロジェクトの表と、項目の「プロジェクト」の欄を追加する |
| `push.js` / `sw.js` | 通知の設定と、通知の表示 |
| `mail.js` | メールの連携の設定（合言葉を作る） |

| `supabase/add-mail.sql` | メールの候補のテーブル、合言葉、受け取り口 |
| `manifest.webmanifest` / `icons/` | ホーム画面に追加するための設定とアイコン |
| `supabase/functions/report/index.ts` | 通知を送るプログラム（Supabase の Edge Function。テストあり） |
| `supabase/add-notifications.sql` | 通知用のテーブル、起きたことの記録、朝10時・夕方17時の予約 |
