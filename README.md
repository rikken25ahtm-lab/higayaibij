# ひがやいびん

2号店オープン準備のための「やること」ページ。

## 続きの作業を始める前に

- **設計メモ**：`docs/design.md` にあります。作る順番（段階）と、各段階の中身はここに書いてあります。
- **進み具合**：第1段階（ページと保存）と第3段階（報告の通知）は完成。第2段階（音声入力）は、AIの要約を貼り付ける方法で代えています。第4段階（メールとドライブの連携）は作成済みで、下の「最初の設定」を行うと動きます（実際の Gmail・Supabase での試運転はこれから）。次は第5段階（結婚式）。
- **ブランチ**：最新の作業は `claude/jolly-lovelace-yp80bl` にあります（`main` は空に近い状態です）。
  公開中のページは `claude/page-save-design-yp3p3n` を表示しているので、ページに反映するときは、そちらにも同じ内容を入れます。
- **公開ページに出るもの**：公開中のブランチに入れたファイルは、アドレスを知っていれば誰でも読めます。
  人に見せたくない内容（連絡先・金額・鍵など）は、リポジトリに入れないでください。

## 今できること（第1段階：ページと保存）

- やることの追加・編集・完了・削除（内容 / 必要な対応 / 進捗〔まだ・途中・返事待ち〕/ 誰に任せるか / 期限）
- AIに決まった形で要約してもらった文を貼り付けて、まとめて追加（確認してから追加。お願い文は画面からコピーできる）
- 期限の近い順に表示。期限切れ・今日・3日以内は色で目立たせる
- 完了した項目は下にまとめて薄く表示
- スマホとパソコンの両方の画面幅に対応
- Supabase に保存してログインで守る（設定したとき）

## 通知（第3段階：朝10時・夕方17時の報告）

毎日 朝10時と夕方17時（日本時間）に、その時間帯に起きたことを、スマホの通知でお知らせします。
Supabase に保存しているときだけ使えます。

- 朝10時：前日17時〜当日10時に起きたこと ／ 夕方17時：当日10時〜17時に起きたこと
- 伝えるのは、やることの追加・期限の変更・完了・削除と、期限の近い件数（「本日まで：0件　翌日まで：0件　3日以内：0件」の形。期限切れも含めて数える）
- 通知を押すとページが開き、その回の報告が一番上に出て、関係する項目に枠がつきます
- メールの連携を設定すると、その時間帯に届いたメールの要点（誰から・件名・添付の数）も加わります

### 最初の設定（1回だけ）

1. **通知を送るプログラムを Supabase に置く**
   Supabase の画面で「Edge Functions」→「Deploy a new function」→「Via Editor」を開き、
   名前を `report` にして、`supabase/functions/report/index.ts` の中身をそのまま貼り付けて Deploy します。
2. **「Verify JWT」をオフにする**
   作った `report` の設定（Details）で「Verify JWT with legacy secret」をオフにして保存します。
   （時刻の予約からの呼び出しを通すためです。本人確認はプログラムの中で行っています）
3. **テーブルと時刻の予約を作る**
   「SQL Editor」に `supabase/add-notifications.sql` を貼り付けて、Run を1回押します。
4. **iPhone のホーム画面に追加する**
   Safari でページを開き、共有ボタン →「ホーム画面に追加」。以後はホーム画面のアイコンから開きます
   （初回はもう一度ログインが必要です）。
5. **通知を受け取る**
   ページ下の「通知」欄で「通知を受け取る」を押し、許可します。
   「今すぐ試しに送る」を押して、通知が届けば完了です。

### 仕組み

- やることの追加・期限の変更・完了・削除は、データベースが自動で記録します（`item_events`）。
- 時刻になると Supabase（pg_cron）が `report` を呼び、`report` がその時間帯の記録をまとめて、登録済みの端末へ通知を送ります。
- 同じ回の報告は1度しか送りません。朝10時台・夕方17時台以外に呼ばれても送りません。
- 通知の署名に使う鍵は `report` が初回に自動で作り、ページからは読めないテーブルに保存します。
- ログアウトすると、その端末への通知は止まります。
- 「通知」欄は、選び終わると畳まれます。ページの一番下の「通知の設定」を押すと、また開けます（試しに送る・やめる）。

## ログイン・新規登録・アカウントの切り替え

Supabase に保存しているとき、最初の画面で「ログイン」と「新規登録」を選べます。

- **新規登録**：メールアドレスと、自分で決めたパスワード（8文字以上）を入れて「登録する」。
  Supabase の設定で「メールの確認」がオンのときは、確認のメールが届くので、その中のリンクを押すと登録が完了します。
- **アカウントの切り替え**：一度ログインしたアカウントは、その端末が覚えます。
  右上の「アカウント」を押して、切り替えたいアドレスを押すだけで切り替わります（パスワードの入れ直しは不要）。
  ログイン画面にも「この端末で使ったアカウント」として出ます。
- 端末が覚えるのは、ログインした状態を保つための鍵だけで、パスワードは保存しません。
  ログインしたままにしているのと同じ扱いなので、**ほかの人と共有する端末では、使い終わったら「ログアウト」** してください
  （ログアウトしたアカウントは、その端末の一覧から消えます）。
- やること・通知・メールの連携は、アカウントごとに別々です。ほかのアカウントの内容は見えません。
- 通知は、その端末でいま使っているアカウントの報告が届きます。

### Supabase の側で確認しておくこと

- 「Authentication」→「Sign In / Providers」で **Allow new users to sign up** がオンになっていること（オフだと新規登録できません）。
- 確認のメールのリンクからページに戻れるように、「Authentication」→「URL Configuration」の **Site URL** に、公開しているページのアドレスを入れておきます。
- ページのアドレスを知っている人は、誰でも新規登録できます（登録しても、ほかの人の内容は見えません）。
  使う人の登録が済んだら、**Allow new users to sign up** をオフに戻しておくと安心です。

## メールとドライブの連携（第4段階）

Gmail でラベル「2号店」をつけたメールが、ページの「メールからの候補」に出ます。
添付は Google ドライブのフォルダ「ひがやいびん 添付」に保存され、やることの項目にリンクがつきます。

- 候補は、確認してから「やることに追加」を押したものだけが、やることになります（勝手には追加されません）。
  新しい項目にするか、いまある項目にリンクだけつけるかを選べます。いらない候補は「追加しない」。
- 見るのは、ラベル「2号店」のついたメールだけです。メールの送信・削除・既読への変更はしません。
  （Gmail の「フィルタ」で、業者のアドレスから来たメールに自動でラベルをつけると便利です）
- 自分が送った返信は候補にしません。確認は15分おきです。
- 添付のフォルダは、Gmail の持ち主だけが見られる状態で作られます。共有するときは、必要な人だけにしてください。
- 届いた候補（差出人・件名・本文の最初の部分）は Supabase に保存され、ログインした本人だけが読めます。

### 最初の設定（1回だけ）

1. **受け取り口を作る**
   Supabase の「SQL Editor」に `supabase/add-mail.sql` を貼り付けて、Run を1回押します。
2. **報告のプログラムを新しくする**（報告にメールの要点を入れるため）
   「Edge Functions」→ `report` を開き、`supabase/functions/report/index.ts` の中身を貼り付け直して Deploy します。
3. **合言葉を作る**
   ページの一番下の「メールの連携の設定」→「合言葉を作る」を押し、出てきた合言葉をコピーします。
   （合言葉が見えるのはこのときだけです。人には見せないでください）
4. **Gmail の側のプログラムを置く**
   メールを受け取りたい Google アカウントで https://script.google.com を開き、「新しいプロジェクト」を作ります。
   最初から入っている文を全部消して、`google/mail.gs` の中身を貼り付け、保存します。
5. **合言葉を入れる**
   左の歯車「プロジェクトの設定」→ 一番下の「スクリプト プロパティ」→「プロパティを追加」で、
   名前（プロパティ）に `TOKEN`、値に 3 でコピーした合言葉を入れて保存します。
6. **setup を1回実行する**
   エディタに戻り、上の関数の選択を `setup` にして「実行」を押します。
   Google の許可の画面が出るので、自分のアカウントを選んで許可します
   （「このアプリは確認されていません」と出たら、「詳細」→「（プロジェクト名）に移動」。自分で置いたプログラムなので問題ありません）。
7. **試す**
   Gmail でメールを1通選んで、ラベル「2号店」をつけます。15分以内（すぐ試すなら、関数 `run` を実行）に、ページに候補が出れば完了です。
   ページの「メールの連携の設定」に「連携しています（最後の確認：…）」と出ます。

### うまくいかないとき・やめるとき

- 候補が出ない：ページの「メールの連携の設定」で、最後の確認の時刻を見ます。
  時刻が出ていなければ、Apps Script の左の「実行数」で失敗の理由を見ます（合言葉の入れ間違いが多いです）。
- 合言葉を作り直したら、Apps Script の `TOKEN` も入れ替えます。
- やめるとき：Apps Script で関数 `stop` を実行し、ページの「メールの連携の設定」→「連携をやめる」を押します。
  届いた候補と、ドライブに保存した添付は残ります。

### 仕組み

- Gmail の側のプログラム（Google Apps Script）が、15分おきにラベルのメールを見て、まだ届けていないメールだけを届けます。
  添付はそのときドライブに保存します。同じメールを2度届けることはありません。
- 届け先は Supabase の受け取り口（`receive_mail`）で、合言葉が合ったときだけ受け取ります。
  Supabase には合言葉そのものは保存せず、照合用の値だけを持ちます。
- メールから「やること」の文を自動で作る（AIの要約）ことは、まだしていません。件名を「内容」の下書きにして、追加の前に直せます。

## 保存について（大事）

`config.js` が空のあいだは、**開いた端末のブラウザの中** に保存します（同期なし・ログインなし）。

`config.js` に Supabase の Project URL と Publishable（anon）キーを入れると、
Supabase に保存するようになり、ログイン画面が出ます。ログインした本人の項目だけが読み書きできます。
テーブルの定義は `supabase/schema.sql` にあります。

## 開き方

ビルドは不要です。`index.html` をブラウザで開くか、次のように配信します。

```
python3 -m http.server 8000   # → http://localhost:8000
```

```
node --test
```
